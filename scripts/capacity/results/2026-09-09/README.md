# 本地媒体、队列与容量优化验证

本次实现覆盖本地元数据直读、空闲队列退避、NFO 冲突选择、历史保留预算、日志预算和探测资源预算。改动尚未提交或部署。下列测量来自隔离的本机 SQLite fixture，不代表远程存储或生产容量承诺。

## 行为与边界

- `local_only + import_metadata_only` 保留源 NFO、图片与媒体文件，仅保存结构化元数据及直读引用。图片 GET 直接读取源，HEAD/条件请求可在读取正文前结束；无图片磁盘缓存。直读可用性写入节流有 4096 项上限。
- 空队列采用 200ms 起步、最高 5s 的退避与抖动；事务提交后本机通知，PostgreSQL 通知及轮询兜底。维护使用数据库租约和限量批次，取消失效 scope 的工作。领取 SQL 显式保留固定活跃状态谓词，让 SQLite 使用既有部分索引；无需额外索引迁移。
- NFO 按人工选择、版本同名、`movie.nfo`、唯一来源及一致合并处理。冲突字段持久化供管理员选择，等待选择期间不因详情访问反复入队。选择与解析任务提交在一个事务中；重复同一选择复用任务。来源变化会重新校验，陈旧结果不可发布。
- 扫描结果按项目记录，项目失败与基础设施失败分开；任务页独立分页加载扫描历史、报告及 NFO 候选，并支持针对受影响项目重试。历史不依赖最近 50 个普通任务。
- 对任务结果、staging、同步页和退休 publication 实施保留预算及分页清理；活动播放引用保护 publication。管理员容量页缓存采样，区分数据库分配空间与业务行数；不自动执行 VACUUM FULL 或重置数据库。
- 默认 Info，临时 Debug 默认 30 分钟并持久化到期时间；默认单文件 32 MiB、目录 256 MiB，同时保留天数约束。日志包含重复错误聚合与脱敏。每个日志目录只允许一个写入者。
- 单次 Probe 默认累计 32 次后端调用、64 MiB、45 秒，覆盖描述文件、元数据查询、分段读取与重试。STRM 不进入整文件下载兜底。存储准入共 32 槽，后台最多 24 槽；解析共 2 槽，后台最多 1 槽。超时不能强制杀死已运行的同步解析器，解析许可一直持有到解析实际结束，防止超时后无限累积解析线程。

## 实测

构建工具链 Node 22.22.3、Rust 1.88.0。baseline 为提交 `832a94b2c` 的独立目录构建，仅加入 fixture 和 SQL 计数观测；8 项对比均为 debug 构建。274 项为 release 构建。测量期间主机存在其他编译和测试负载，未清空操作系统页缓存。

| 8 项空闲 15 秒样本 | baseline | 本次改动 |
|---|---:|---:|
| 服务 CPU，单核百分比 | 2.20% | 0.20% |
| SQL 语句/秒 | 119.98 | 2.80 |
| 领取查询/秒 | 34.64 | 1.40 |
| 两次扫描及请求总耗时 | 209.41 秒 | 217.54 秒 |

SQL 计数是驱动语句计数，**不是事务数**；不能据此声称达到事务率指标。短样本空闲 CPU 明显降低，但扫描耗时未显示改善。

| release 容量 | 结果 | 说明 |
|---|---|---|
| 274 项 × 并发 1/5/20 | 完成 | 两次扫描约 133.50/158.97 秒，总计 319.10 秒 |
| 2740 项 | 达到停止线 | 900.02 秒时主动停止，未完成两次扫描与并发矩阵 |
| 27400 / 82200 项 | 未执行 | 按逐级停止策略，不继续扩大负载 |

274 项服务峰值 RSS 58.47 MiB；空闲 CPU 0.27%，SQL 3.00 条/秒。两次扫描后 catalog 与 direct reference 均为 274，三张 asset 表始终为 0，asset 文件为 0，源文件摘要不变。数据库分配空间从第一次扫描后约 4.52 MiB 增至第二次约 6.04 MiB，空闲页约 0.24 MiB；保留期内历史 publication、结果和同步记录会增加，零拷贝不等于数据库零增长。

| 并发 | 列表 P95 | 海报 P95 | PlaybackInfo P95 |
|---|---:|---:|---:|
| 1 | 2.40 ms | 1.08 ms | 2.58 ms |
| 5 | 3.42 ms | 2.18 ms | 9.15 ms |
| 20 | 13.69 ms | 9.62 ms | 32.99 ms |

每类分别采样 20/25/100 次。PlaybackInfo 响应时间不等于播放首帧。

真实 Chrome 通过 `requestVideoFrameCallback` 观察微型 16×16 MP4，首次进入播放约 331.3 ms、重复约 71.3 ms，各一次。仅验证浏览器播放链路，不外推真实电影或远程 STRM 首帧。浏览器还验证 NFO 年份冲突选择后只更新目标项目、独立扫描历史与报告加载、容量面板；HTTP 验证图片 GET 200、HEAD 200 空正文、If-None-Match 304 空正文。

原始测量见 [baseline](baseline-8.json)、[8 项改动版](debug-04.json)、[274 项 release](release-274.json)、[2740 项停止记录](release-2740-r2.json)。测量发生在最终领取索引谓词修复前，因此原始 JSON 保留 `SCAN job`；修复后独立 EXPLAIN 回归测试验证 scoped/unscoped 领取均使用 `ix_work_jobs_claim_active`，不冒充重新测量过全部延迟。

2740 项第一次尝试因测量连接遇到 SQLite busy 停止；测量工具加入有界重试后第二次达到总时间预算。不能把该 busy 解释成服务死锁。早期报告仅在两次扫描完成后保存扫描数组，因此第二次停止记录没有可靠的部分扫描耗时；工具现已改为逐次记录，旧结果未补造。

## 复现

从仓库根目录运行，选择全新临时目录：

```sh
cargo +1.88.0 build -p tjxy-server --example capacity_server --release --locked
python3 scripts/capacity/run.py --root /tmp/tjxy-new-capacity --items 274 --concurrency 1 5 20 --max-seconds 600 --max-rss-mib 2048 --max-disk-mib 2048 --server-binary target/release/examples/capacity_server --report /tmp/tjxy-new-capacity-report.json
```

fixture 生成独立数据库和私有凭据，不能指向现有安装；报告不包含凭据。状态 `stopped` 或退出码非 0 均不得记为通过。更大一级应在前一级完成且资源允许后启动。远程测试需提供独立来源及请求/流量预算，目前未测真实远程延迟、限流和多进程长时稳定性。

## 兼容与回滚

新增迁移 076–078 分别保存维护租约、NFO 选择与日志预算。旧迁移 040 让即将删除的表连同其外键索引一起移除，054 回滚时恢复 MySQL 外键所需的单列索引，068 保留 MySQL 默认值，069 使用 ASCII 大小写敏感的 Passkey Base64URL 标识列，使完整 1024 字符键适配 MySQL 索引限制；数据格式没有改为不区分大小写。

上线前备份数据库及配置。回滚先停止工作领取并排空在途写入，再更换旧二进制；保留新增表列，通常无需执行 down。旧版本不认识新的日志模式字段时仍有兼容的旧级别表示，回滚后检查实际日志级别。不要在任务仍运行时删除 NFO 选择或保留状态，不自动降级/丢弃人工 NFO 决策。必须回退结构时只在隔离副本验证 down/up，再按备份恢复策略操作。日志目录共享会被写入锁拒绝，应为每个服务实例分配独立目录。

## 增量口径与未覆盖指标

以 274 项首次扫描相对创建媒体库前的 SQLite `dbstat.payload` 增量归一到每千项目：元数据 1225.28 KiB、关系与直读引用 467.33 KiB、存储对象索引数据 1930.18 KiB、运行历史与 publication 3022.05 KiB、各索引 payload 3706.99 KiB、其他配置 1.87 KiB。分类明细见 [归一化增量](normalized-footprint.json)。这些数字不含页头、页空闲和文件预分配；实际文件分配增量为 3,387,392 字节。样本 NFO 只含简单元数据，不能按此推算实际人物关系丰富的大库，更不能视为已完成每千真实影片容量验收。

本次没有实际数据库事务率、PostgreSQL/MySQL 空闲 CPU 前后对比、通知到领取的生产 P95、队列等待分布、扫描 CPU 曲线、真实远程首帧 P50/P95/最大值及来源变化后的首帧分布。通知、租约、版本隔离、重复入队合并和来源变化由回归测试覆盖；这些正确性测试不能代替上述性能测量。重复扫描的 publication 历史仍增长，保留机制测试覆盖到期清理与活动引用保护，但本机短测不等于跨保留窗口的长期稳定性验收。
